# Frontend parity tracker — EspoCRM 9.1.7

The target is full replacement of the interactive EspoCRM frontend while retaining EspoCRM as the application backend. “Generic” means implemented against live metadata and REST endpoints; it does not count as parity for a scope that has its own controller, view behavior, or actions.

## Inventory used as the baseline

- Source baseline: official EspoCRM `9.1.7` tag at `4baab4dff4342ed1b194015407c8bc74b4cc9a7d`, client source and server metadata.
- Server metadata currently reports 88 scopes, 75 entity scopes, and 23 tab scopes.
- The 9.1.7 client tree contains 878 view source files and 37 controllers across the core client and CRM module.
- The source has 83 first-level view folders when core and CRM module views are combined. These include custom admin managers, email, import, calendar, user/security, portal, templates, streams, dashlets, and entity-specific views.
- Per-family source counts and replacement mappings are tracked in [VIEW_FAMILY_AUDIT.md](VIEW_FAMILY_AUDIT.md); no native family is considered complete based only on generic CRUD.
